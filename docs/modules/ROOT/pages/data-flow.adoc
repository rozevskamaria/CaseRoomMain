= Data Flow

This page traces every data path in the system: the full component graph, then sequence
diagrams for the three most important flows — a consultation turn, authentication, and
final-answer feedback.

GitHub, see `docs/data-flow.md` — a mirror of these diagrams in Markdown, which GitHub
renders natively. This page is the canonical source; keep the mirror in sync.

== Consultation turn

The defining flow of the application: a student sends a message to the AI parent. The
mutation appends events and decides the branch; only the `parent` branch opens the SSE
stream, which is where the LLM reply is generated and persisted.

++++
<pre class="mermaid">
sequenceDiagram
    autonumber
    participant B as Browser (SPA)
    participant G as GraphQL /graphql
    participant S as SessionService
    participant R as Action router
    participant P as PostgreSQL (events)
    participant E as SSE /sse/parent/{id}
    participant A as Anthropic API

    B->>G: sendMessage(sessionId, text)
    G->>G: require_attempt_access(owner, write)
    G->>S: send_message()
    S->>P: load events → fold projection
    alt English attempt
        S->>R: heuristic CaseEngine (is_test_order?)
    else Latvian / hybrid routing
        S->>A: tool-use routing (order_test | request_exam | ask_parent)
    end
    alt test order
        S->>P: append TestOrdered + LabResultShown (+ nudges)
    else exam request
        S->>P: append ExamPerformed (+ practice note)
    else parent turn
        S->>P: append StudentMessageSent + ParentReplyRequested<br/>(system prompt + trimmed history)
    end
    S->>P: sync projection cache (phase/status)
    G-->>B: branch + updated session projection
    opt branch == parent
        B->>E: open EventSource (session cookie)
        E->>E: resolve user, verify attempt owner
        E->>P: load pending ParentReplyRequested
        E->>A: messages.stream(parent prompt, history)
        A-->>E: text deltas
        E-->>B: data: {delta} … (rendered live)
        E->>P: append ParentReplyAppended (+ exam nudge on 5th reply)
        E-->>B: data: {done}
    end
</pre>

== Authentication (passwordless magic link)

Six-digit RSU student numbers, locked `@rsu.edu.lv` addresses, opaque server-side sessions.
Responses are identical whether or not an account exists, so login names cannot be enumerated.

++++
<pre class="mermaid">
sequenceDiagram
    autonumber
    participant B as Browser
    participant G as GraphQL
    participant AU as AuthService
    participant R as Redis
    participant PG as PostgreSQL (users)
    participant Q as ARQ worker
    participant M as Resend

    B->>G: registerStudent(loginName)
    G->>AU: register_student(login, ip)
    AU->>R: rate limit (per IP + per subject)
    AU-->>G: ok (constant response)
    AU->>PG: create user — pgp_sym_encrypt(PII), hmac(login) hash
    AU->>R: store magic-link token (TTL 15 min)
    AU->>Q: enqueue send_magic_link
    Q->>M: email → {login}@rsu.edu.lv
    M-->>B: link https://caseroom.tech/auth/verify?token=…
    B->>B: explicit confirm page (no auto-consume)
    B->>G: consumeMagicLink(token)
    G->>AU: consume_link(token, ip)
    AU->>R: rate limit consume per IP
    AU->>R: GETDEL token (single use)
    AU->>PG: activate user + stamp consent version
    AU->>R: create opaque session
    G-->>B: Set-Cookie (httpOnly · Secure · SameSite=Lax)
</pre>

== Where data lives

[cols="1,2,2"]
|===
|Store |Data |Protection

|PostgreSQL `users`
|login number, email, full name
|pgcrypto `pgp_sym_encrypt` at rest; lookups via peppered HMAC hash; decrypted only for the requesting principal

|PostgreSQL `events`
|full attempt transcript as append-only events
|owner/admin/assignment-scoped-staff reads only; research access is scrubbed (allow-listed categorical fields, no free text)

|PostgreSQL `cases*`
|clinician-authored clinical content, versioned
|published versions immutable; no AI writes any clinical field

|Redis
|sessions, magic-link tokens, rate-limit counters, job queue
|opaque 256-bit tokens; single-use links; internal network only

|Anthropic API
|case prompts + conversation excerpts (transient)
|server-side key; no student identifiers included in prompts
|===
